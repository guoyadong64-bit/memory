# V5 查询条件与见证子图召回

沿用 50 段视频、2,901 道开发题的共享视觉观测。新增基于实体、事件角色与观测帧的倒排关联索引；保留原超图语义种子，同时从全局见证索引补召回，按查询条件和证据多样性重新分配候选预算。位置可以是对象的筛选条件，不会被直接当成查询要求的对象。时序邻接仍是不完整事件候选，不作为新的已证实事件。

每题最多 32 个候选帧、20 个独立观测视图、40,000 字节检索证据和 12 张答题原图。视图按来源组织，集合内观测不自动成为同一事件；身份 ID、原始观测、角色与事件片段来源保持可追溯。答题原图按查询相关性及多样性选择；回答提示、格式归一化、验证、输出上限和评分规则沿用原公共实现。历史基线源文件与结果不改动。

在 `E:\code\smp` 执行无模型请求的全量召回审计：

```bat
E:\conda\envs\smp-memory\python.exe -u -m benchmarks.run_validation50_hypergraph_v5 --audit-only
```

审计只复用旧检索种子，读取原观测，按新规则生成候选，再由评分器读取官方标注。检索接口没有标注、任务编号、题型、正确性或旧答案输入。`offline_coverage_audit.json` 和 `AUDIT.md` 保存全部题目、有解题、实际原图覆盖率、各类结果与理论上限；这不能提供新的答题正确率。

真实模型全量验证命令：

```bat
E:\conda\envs\smp-memory\python.exe -u -m benchmarks.run_validation50_hypergraph_v5
```

默认结果目录：`runtime\experiments\hypergraph_validation50_v5`。全部题目由 V5 重新作答，不把旧正确题直接拼入新版总分。复用已封存视觉观测及兼容的旧嵌入响应，不复用旧答案。控制台显示进度、正确数、请求数和 token；支持同一命令断点续跑，无累计 token 硬上限。API 用量包含新增检索与回答，费用以平台账单为准。

当前 140 道题没有有效目标帧，计入全部题目时覆盖率最高为 2761/2901 = 95.1741%。有解题覆盖率与全部题目覆盖率必须同时报告，不能用前者冒充后者。不能通过开放全部 96 帧、读取答案选帧或挑选成功结果来实现覆盖目标。这 50 段已经参与开发，需要独立测试集才能判断泛化。

结果配置及代码哈希被冻结；改变实现后请用新的 `--run-dir`，不要覆盖已完成的正式结果。`--check-only` 仅校验输入，不请求模型。审计输出与真实模型输出分别保存在独立文件中。
